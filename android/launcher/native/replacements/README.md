# Нативные замены для Android-портов

Эти исходники подключаются в сборку хоста игры. Стабильная граница для замены — вызов движка с известным ABI. Адрес функции, представление указателей гостя, формат данных и набор шейдеров устанавливают отдельно для каждого издания.

| Файл | Что подключить | Как проверить интеграцию |
|---|---|---|
| `aaudio_output.c`, `aaudio_output.h` | Один управляющий поток владеет `port_audio_output` с нулевой начальной инициализацией. Передать `port_audio_open` частоту движка и его микшер interleaved stereo PCM16. Линковать `aaudio`, API 26+. | Обработать ошибку открытия, паузу и смену маршрута. При `AAUDIO_STREAM_STATE_DISCONNECTED` закрыть поток и открыть заново. Callback возвращает число заполненных кадров, остаток заполняется тишиной. Закрыть поток перед освобождением микшера. |
| `lua_chunk.c` | `port_lua_chunk` загружает и вызывает chunk в переданном нативном `lua_State`. Версия Lua, конфигурация чисел, bytecode, allocator и регистрация функций должны совпадать с игрой. | Проверить значения и стек при успехе и ошибке на реальном скрипте. Для 32-битного гостя переводить дескрипторы и userdata на границе. У Frostpunk имеется пример Lua 5.1.1. |
| `inflate_zlib.c` | Декодирование потока zlib в буфер ожидаемого размера через системную `libz`. | Проверить размер результата, конец потока, лишний хвост и усечение. У raw DEFLATE, gzip и архивов с конкатенацией другой контракт. |
| `lzma_alone.c` | `port_lzma_alone` принимает .lzma с 13-байтным заголовком, ожидаемый размер и предел памяти. Линковать собранную для arm64 liblzma. | Сопоставить заголовок, словарь, декодированные байты и ошибки с декодером игры. Для XZ и raw LZMA выбрать соответствующий декодер. |
| `crc32_ieee.h` | `port_crc32_ieee` продолжает CRC-32 IEEE от переданного seed. ARM-команды включаются при `HWCAP_CRC32`, для остальных устройств используется zlib. | Для `123456789` с seed 0 результат `0xCBF43926`. Проверить дробление, невыровненные входы и пустой блок. У CRC32C другой полином. |
| `vulkan_driver.h` | На пути Turnip/PanVK передать каталог hooks и конкретную библиотеку в `port_open_vulkan_driver`. Функция возвращает `vkGetInstanceProcAddr` загруженного драйвера. Её уже использует общий `vulkan_probe.c`. | Получать instance/device dispatch из того же драйвера. Применять выбранный лаунчером `PORT_TURNIP_DRIVER` или `PORT_PANVK_DRIVER` и подтвердить идентичность физического устройства. Запасной системный загрузчик получает отдельный результат. |
| `crash_marker.h` | В инициализации игры вызвать `port_crash_marker_open()`, в существующей ветке фатального сигнала — `port_crash_marker_signal(fd, sig)`. Дескриптор принадлежит процессу игры. | Общий лаунчер читает сигнал и PID из приватного файла конкретного издания. На следующем запуске запись сбрасывается. Пример подключения — Heroes IV, `android/host/crash.c`. Запуск с записью `renderer_failure.h` лаунчер называет `renderer failure: …`, а не сигналом. |
| `renderer_failure.h` | Политика отказа рендерера (решение владельца 24.11.2026): без перехода на другой рендерер или драйвер. При старте после `Launch.attach` — `port_renderer_failure_init()`, после первого успешного present — `port_renderer_presented()`, при отказе — `port_renderer_failed(reason, device_lost)` (0: не запустился — драйвер, идентичность, instance/device/surface/swapchain/EGL, нужная возможность; 1: `VK_ERROR_DEVICE_LOST`, потеря EGL-контекста, сброс GL robustness), затем выход: из потока с JNI — `Launch.rendererFailed`, иначе `_exit()`. | Любой поток и обработчик сигнала: только `open`/`write`/`close`, `getpid`, `clock_gettime`; без аллокаций (`tests/test_renderer_failure.py` проверяет импорты сборок aarch64/armv7, C и C++). Запись в `PORT_RENDERER_FAILURE` читает `RendererFailure.java`; лаунчер предлагает следующий рендерер ([INTEGRATION.md](../../docs/INTEGRATION.md), «Renderer failure»). Состояние — одно слабое определение на библиотеку: `presented` и `failed` вызывать из одной `.so`. |

Рабочие примеры границы аудио имеются в The Sims 2 (`android/host/audio.c`), Prey (`prey_aaudio_sink.c`) и BioShock (FMOD Ex и Bink). Очередь микшера, синхронизация видео, выбор устройства и обработка потери фокуса принадлежат конкретной игре. AAudio вызывается из публичного NDK. [Руководство Android по AAudio](https://developer.android.com/ndk/guides/audio/aaudio/aaudio)

Для графики общий код принимает интервалы фактически показанных кадров в `native/frame_times.h` и измеряет форматы в `native/vulkan_probe.c`. У D3D9, D3D10 и D3D11 различаются контракт ресурсов, состояния, отражение шейдеров и кэш пайплайнов. Примеры подключения к движку собраны в [D3D9](../../../wiki/23-d3d9-to-native-gles-vulkan.md), [D3D10](../../../wiki/24-d3d10-to-native-gles-vulkan.md), [D3D11](../../../wiki/22-d3d11-to-native-vulkan.md) и [нативных заменах](../../../wiki/25-native-replacements.md).

Узкие исправления привязываются к движку, GPU, API и версии драйвера, на которых воспроизведён дефект. Примеры для переноса — переключатель `mali_g51_workaround` в The Sims 2 и отдельные ветки Frostpunk. Конкретные условия и открытые вопросы перечислены в [описи портов](../../docs/PORT_AUDIT.md). Базовые вызовы новых реализаций проверяет [replacements_check.c](../../tests/replacements_check.c).
